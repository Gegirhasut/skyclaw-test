# Тестовое задание: аванс по договору

Около 2-3 часов. Работа - в Claude Code.

## Контекст

Компания заказывает работы у подрядчиков: съёмки, дизайн. Договор с подрядчиком - это общая сумма на несколько работ. Платим по договору авансом и остатками, иногда платёж привязан к конкретной работе.

Письмо бухгалтера:

> Мне нужен отчёт: по каждой работе - сколько уже выплачено и сколько осталось оплатить, и итог по каждому договору. Сейчас считаю в таблице руками и путаюсь: платежи по договору ни к какой работе не привязаны, а мне надо понимать, за что мы уже рассчитались. Отчёт нужен на дату, для проверки - на 10.11.2026.

## Что есть

Папка `data/`: договоры, работы, платежи и описание формата в `FORMAT.md`.

Бухгалтер в отпуске и на связи не будет, других источников, кроме `data/`, нет. Где данных не хватает, решите сами и запишите допущение в `DECISIONS.md`.

## Что сдать

1. **Программа** на Python или TypeScript - скрипт, CLI или маленький HTTP-сервис, на ваш выбор. По файлам из `data/` и дате она строит отчёт:
   - по каждой работе: цена, выплачено, осталось оплатить;
   - по каждому договору: итоги.

   Напишите, как её запустить: мы запустим сами.

2. **Файл `DECISIONS.md`** - решения, которые вы приняли по ходу работы. По каждому решению коротко:
   - что решали;
   - какие были варианты;
   - что выбрали и почему;
   - что изменится в отчёте, если выбор окажется неверным.

   Пример оформления на постороннюю тему:

   > **Формат отчёта.** Варианты: таблица в консоли или файл CSV. Выбрал CSV: его можно открыть в таблице. Если неверно, поменяется только вывод, расчёт останется прежним.

3. **Записка бухгалтеру** на 5-10 строк простым языком: как читать отчёт и что ей нужно подтвердить, когда вернётся.

4. **Полный транскрипт работы с Claude Code** - экспорт командой `/export`, без правок. Если сессий было несколько - все. Ключи и пароли, если попали в сессию, можно вырезать.

Интерфейс, база данных и docker не нужны. Деньги считайте точно, до копейки, без float.

Не успели всё - напишите, что осталось и что бы вы сделали дальше.

## Как запустить

Нужен Python 3.10 или новее. Внешних зависимостей у программы нет. Команды выполняются из папки `candidate-B`.
Если команда `python` у вас называется иначе — на macOS и Linux обычно `python3`, на Windows может быть `py` — подставьте её.

```bash
python -m advance_report data 2026-11-10
```

Дату можно писать и так: `10.11.2026`. Отчёт печатается в консоль, а CSV сохраняются в `./report/`:

- `works_2026-11-10.csv` — по каждой работе: статус на дату, цена, выплачено (в том числе по привязке и из общих платежей), осталось оплатить, к оплате сейчас, в очереди;
- `contracts_2026-11-10.csv` — итоги по договорам и строка «Итого»;
- `notes_2026-11-10.csv` — примечания: что проверить, пояснения к расчёту, события после даты отчёта.

Параметры:

| Параметр | Что делает |
|---|---|
| `--out DIR` | папка для CSV (по умолчанию `./report`) |
| `--csv-format excel` | по умолчанию: `;`, десятичная запятая, UTF-8 с BOM, открывается в русском Excel двойным щелчком |
| `--csv-format plain` | `,` и точка, UTF-8 без BOM, для других программ |
| `--no-csv` | только вывод в консоль |

Коды выхода:

| Код | Значение |
|---|---|
| `0` | отчёт построен |
| `1` | в данных ошибки; печатается полный список, отчёт не строится |
| `2` | неверные аргументы, например некорректная дата |
| `3` | внутренняя ошибка сверки сумм |
| `4` | не удалось сохранить CSV (например, `--out` указывает на файл) |

- **отчёт на 12.11**: видна переплата по D-2;

- **границы дат**;

- **CLI и CSV**;
- **300 случайных наборов данных**: на них проверяется, что суммы сходятся до копейки.

## Как устроен расчёт

Подробно расчёт описан в `DECISIONS.md` и в начале `advance_report/calc.py`.

1. Статусы в выгрузке даны «на сейчас», поэтому состояние каждой работы и платежа на дату отчёта восстанавливается по датам приёмки, отмены, оплаты и возврата.
2. Отменённые работы в расчёт не входят. Возвращённые платежи не учитываются. Платежи в очереди не считаются выплаченными.
3. Выплаченное раскладывается так:
   - сначала платёж с привязкой идёт на свою работу;
   - затем общие платежи закрывают принятые работы в порядке даты приёмки;
   - потом запланированные по номеру;
   - излишек — переплата по договору.
4. Очередь раскладывается так же, поверх выплаченного.
5. Деньги хранятся только в `Decimal` с копейками, float нигде нет. Расчёт сам проверяет, что «выплачено по работам + переплата = выплачено всего», и без сходящихся сумм отчёт не выдаёт.
